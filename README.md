# 밥상탐험대 (Nutri Deck) 🍚

**밥상탐험대(Nutri Deck)** 는 공공 식품·영양 데이터를 활용하여 영양정보를 게임으로 학습할 수 있도록 만든 웹 기반 교육 보드·카드 게임입니다.

단순히 영양성분표를 읽는 것이 아니라,

**영양정보 확인 → 비교 → 메뉴 선택 → 영양성분 합산 → 조건 판단 → 결과 확인**

과정을 반복하면서 음식 선택에 따라 한 끼의 영양 구성이 어떻게 달라지는지 직접 경험할 수 있도록 설계했습니다.

🔗 Demo: https://nutri-deck.vercel.app

---

## 🎮 게임 소개

- 1명부터 최대 4명까지 플레이할 수 있습니다.
- 플레이어는 영양 관련 문제와 미션을 해결해 점수를 얻습니다.
- 획득한 점수만큼 보드 위의 말을 이동합니다.
- 가장 먼저 `GOAL`에 도착한 플레이어가 승리합니다.
- 게임은 `LEVEL 1 → LEVEL 2 → LEVEL 3`으로 진행됩니다.

단계가 높아질수록 영양정보를 활용하는 방식도

**비교 → 조합 → 복합조건 판단**

으로 확장됩니다.

---

## 🧠 LEVEL 1 — 영양정보 기억 및 비교

음식 카드의 영양정보를 **15초 동안 확인**한 뒤 주어진 문제에 맞는 음식을 선택합니다.

예시:

- 밥 3장 중 탄수화물이 가장 높은 음식
- 반찬 3장 중 단백질이 가장 높은 음식
- 국 3장 중 나트륨이 가장 낮은 음식
- 전체 9장의 음식을 비교하는 문제

### 점수

- 음식 3장 비교 문제 정답: **1점**
- 전체 9장 비교 문제 정답: **2점**

---

## 🍱 LEVEL 2 — 한 가지 조건을 만족하는 한 끼 구성

밥·국·반찬 카드를 조합하여 하나의 영양 조건을 만족하는 한 끼를 구성합니다.

예시:

- 540~800 kcal
- 단백질 18g 이상
- 탄수화물 50g 이상
- 나트륨 1,500mg 이하
- 지방 22g 이하
- 당류 25g 이하

선택한 음식의 영양성분을 자동으로 합산하여 미션 조건 충족 여부를 판정합니다.

각 문제는 최대 **3회까지 다시 도전**할 수 있습니다.

---

## 🥗 LEVEL 3 — 여러 영양조건을 고려한 한 끼 구성

LEVEL 3에서는 여러 개의 영양 조건을 동시에 만족하도록 음식 카드를 조합합니다.

예시:

```text
단백질 18g 이상
+
탄수화물 50g 이상
+
나트륨 1,500mg 이하
```

처음 구성한 식단이 조건을 만족하지 못하면 결과를 확인한 뒤 음식을 교체하고 다시 도전할 수 있습니다.

이를 통해 단순히 정답을 맞히는 것이 아니라,

**선택 → 결과 확인 → 메뉴 수정 → 재확인**

과정을 반복하도록 설계했습니다.

> 게임의 영양 조건은 교육용 미션 기준이며 개인 맞춤형 식단이나 의료적 영양 기준을 의미하지 않습니다.

## 📊 데이터

영양정보는 다음 공공데이터를 결합하여 구성했습니다.

### 메뉴 및 재료 정보

**농촌진흥청 국립농업과학원 농식품 식단관리 메뉴젠(MenuGen) 음식·재료·조리 정보**

메뉴별 구성 재료와 재료 중량 정보를 활용했습니다.

### 영양성분 정보

**국가표준식품성분 Database 10.4**

식품별 가식부 100g 기준 영양성분 데이터를 활용했습니다.

### 메뉴별 영양성분 계산

```text
재료별 영양성분
= 국가표준식품성분DB의 100g당 영양값
× 메뉴젠 재료 중량(g) / 100

메뉴 영양성분
= 메뉴에 포함된 재료별 영양성분 합계
```

전체 데이터에서 게임에 사용할 수 있도록 전처리한 **36개의 완성 메뉴 데이터셋**을 현재 게임에 사용하고 있습니다.

## 📌 주요 영양정보

각 음식 카드는 다음 정보를 포함합니다.

```ts
Food {
  food_code
  food_name
  category
  energy_kcal
  carbohydrate_g
  protein_g
  fat_g
  fiber_g
  sugar_g
  sodium_mg
  menu_weight_g
}
```

게임에서 주로 활용하는 영양소는 다음과 같습니다.

`열량 · 탄수화물 · 단백질 · 지방 · 식이섬유 · 당류 · 나트륨`

## 💡 구현 포인트

### 1. 공공데이터를 게임 데이터로 변환

메뉴젠의 메뉴·재료 정보와 국가표준식품성분DB를 연결하여 메뉴 단위의 영양정보를 계산했습니다.

공공데이터를 그대로 보여주는 것이 아니라 게임에서 바로 사용할 수 있는 음식 카드 데이터로 가공했습니다.

### 2. 영양성분 자동 합산

플레이어가 선택한 음식 카드의 영양값을 합산하여 한 끼의 총 영양성분을 계산합니다.

### 3. 미션 자동 판정

LEVEL별 영양 조건을 코드로 정의하고 선택한 한 끼가 조건을 만족하는지 자동으로 평가합니다.

### 4. 단계적 학습 구조

```text
LEVEL 1
영양정보 기억·비교
        ↓
LEVEL 2
하나의 조건을 고려한 한 끼 구성
        ↓
LEVEL 3
여러 조건을 동시에 고려한 한 끼 구성
```

영양정보를 단순히 암기하는 것이 아니라 단계가 올라갈수록 실제 선택에 활용하도록 구성했습니다.

## 📚 배운 점

공공데이터를 서비스에 활용하려면 데이터를 가져오는 것보다 **사용자가 실제로 이해하고 활용할 수 있는 규칙으로 변환하는 과정**이 중요하다는 점을 배웠습니다.

특히 영양성분 데이터를 단순히 보여주는 것보다 사용자가 직접 음식을 비교하고 조합한 뒤 결과를 확인하도록 설계했을 때 데이터가 학습 경험으로 연결될 수 있다는 것을 확인했습니다.

또한 서로 다른 공공데이터를 연결할 때는 식품코드, 재료 중량, 영양성분 기준처럼 데이터 간 기준을 명확하게 맞추는 과정이 중요하다는 점을 경험했습니다.
